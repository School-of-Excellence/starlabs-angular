## TL;DR
**The migration is proven.** On stock **Flutter 3.44.1 (Dart 3.12.1) + Xcode 26.5**, the app now compiles,
builds an **arm64** iOS-simulator binary, **installs** and **launches** on the iPhone 17 Pro (iOS 26)
simulator. The whole reason the app was pinned to a hand-patched **Flutter 3.29.3** — and the cascade of
Xcode-26.5 hacks that came with it — is **gone**. What remains is integration (wire into the e2e harness,
decide team adoption, push) and running the actual participant e2e on 3.44.

## Why this migration exists
The app was stuck on a local hand-patched **Flutter 3.29.3** SDK (`~/flutter-sdks/flutter`) because two
deps wouldn't COMPILE on Dart 3.12. That pin then required: patched `flutter_tools` source, an
x86_64/arm64 sim fight, and an Xcode-26.5 `-destination` workaround. Moving to **stock 3.44** removes all
of it — 3.44 is the toolchain built for the Xcode-26-era.

  They mirror the *tiny* surfaces actually used (face detection: only `lib/profileimage.dart`; ffmpeg:

- → **Commit `71020fd`**. Verified: `lipo -archs Runner` = `x86_64 arm64`; `simctl install` **rc=0**;
  `simctl launch` **rc=0** (PID 21389); screenshot = live app notification dialog.

## How the stubs are applied (CRITICAL to understand)
The stubs are wired ONLY through a **`pubspec_overrides.yaml`** that is **local & gitignored** (via
`.git/info/exclude`). It re-states `win32: ^5.0.0` (pubspec_overrides REPLACES, not merges) plus the two
stub paths. **Device / production / CI builds have no overrides file → they use the REAL plugins.** The
stubs are committed but inert without the override.

`pubspec_overrides.yaml` contents:
```yaml
dependency_overrides:
  win32: ^5.0.0
  google_mlkit_face_detection: { path: packages/sim_stubs/google_mlkit_face_detection }
  ffmpeg_kit_flutter_new:      { path: packages/sim_stubs/ffmpeg_kit_flutter_new }
```

## Reproduce the arm64 sim build (exact incantation)
Use **stock** `/opt/homebrew/bin/flutter` (3.44.1) — NOT `~/flutter-sdks/flutter` (3.29.3).
Prereqs already on this machine (gitignored; a fresh machine must regenerate): `lib/firebase_options.dart`,
`ios/Runner/GoogleService-Info.plist`, and the `~/e2e-bin/flutterfire` no-op stub.
```bash
cd breakthroughs-flutter
# ensure pubspec_overrides.yaml (above) exists, then:
flutter pub get
rm -f ios/Flutter/Generated.xcconfig .flutter-plugins .flutter-plugins-dependencies   # see GOTCHA
PATH="$HOME/e2e-bin:$PATH" flutter build ios --simulator --debug      # ~7 min
lipo -archs build/ios/iphonesimulator/Runner.app/Runner               # expect: x86_64 arm64
xcrun simctl boot "iPhone 17 Pro"; open -a Simulator
xcrun simctl install booted build/ios/iphonesimulator/Runner.app      # expect rc=0
```

## GOTCHAS (these cost hours — don't repeat)
1. **`flutter clean` does NOT rewrite `ios/Flutter/Generated.xcconfig`.** A stale
   `EXCLUDED_ARCHS[sdk=iphonesimulator*]=i386 arm64` (left from a real-plugin build) silently forces
   x86_64 even after the stubs remove the bad pods. **`rm` it** before building; do NOT rely on clean.
2. `pub get` **succeeds** on 3.44 for deps that don't COMPILE — green resolution ≠ Dart-3 compatible.
3. pub.dev's "arm64-simulator" arch label for `ffmpeg_kit_flutter_new` was **misleading** — inspect the
   actual `.framework`/podspec, not the metadata.
4. Use `flutter pub upgrade <pkg>` (not `pub get`) to move a single locked version.

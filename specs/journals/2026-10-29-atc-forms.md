## 1. Data structure — why it ended up this small
- **`atc model.forms: [{ formid, filledby }]`.** `filledby` is `specialist | participant`, has no default (the admin must
  pick), and the list is kept in form-name order. Locked by the operator before any View ATC work.
- **`atc_alpha/{atcid}.formsubmitted: { [deliveryFormId]: formsByClientId }`.** The operator rejected richer per-ATC
  form state ("keep only two fields", "keep it simple"). A map, not an array, so one form = one key, and FieldPath keeps
  a form id with dots a single key. An ATC edit copies it to the new version for free: `replicateATC` spreads the live
  doc.
- **`firestore-atc · atc_form_requests/{atcid}_{formid}`: `{ atcid, formid, profileid, product, sentby, sentat, answerid? }`.**
  - A **separate collection, not `appactionpending`**. Integrating with app action pending meant reworking its
    manage screen; a new collection was the smaller scope. It will also carry the parked "outside the model / sponsor"
    requests.
  - The doc id `{atcid}_{formid}` makes Send idempotent (a double click writes the same doc). `answerid` present =
    Resent (the specialist wants that answer edited).
- **Status rules:**

  | `formsubmitted` key | request | status |
  |---|---|---|
  | no | no | Not sent |
  | no | yes | Sent |
  | yes | no | Submitted |
  | yes | yes, with `answerid` | Resent |

- **Requests match the current ATC id OR any earlier version id**, because an edit gives the ATC a new id while a request
  may have been sent before the edit.

## Request contract — FINAL (2026-10-29, after the Flutter session; supersedes the status rules above)
- **One request doc per ATC + form for the ATC's whole life** (operator). Created as `{atcid}_{formid}` on the first
  Send. A Send/Resend after an ATC edit **rewrites that same doc and keeps its original `atcid`**: the participant app
  builds the doc id from `atcid`, and both apps follow `upgradedto` to the latest version. View ATC waits for the
  requests to load before it shows any Send, so a duplicate can't be created by clicking early.
- **`formstatus`** (added by the Flutter session, operator's choice): `'sent'` = waiting on the participant,
  `'submitted'` = the app submitted it. **The doc is kept after submit** as the record of what was sent; only
  **Revoke** deletes it. Send/Resend is a `setDoc` without merge, so a Resend clears `'submitted'` and sets
  `answerid` (= an edit of that answer).
- **Specialist row:** waiting (`formstatus == 'sent'`) → Sent · Revoke / Resent · View, Revoke. Not waiting →
  Not sent · Send / Submitted · View, Resend.
- **App submit:** latest-version check → save the answer (a resubmit edits the same answer, the previous copy goes to
  `formsByClient log`) → one transaction: `formsubmitted.{formid}` on the latest version + `formstatus: 'submitted'`.
- **Soft-deleted form already sent and still waiting:** the web keeps Revoke enabled and does not say "no longer
  required" (operator, option a); the app still asks the participant to fill it (Flutter D3).
- The full workflow table: Flutter `specs/journals/2026-10-29-atc-participant-forms.md` §3.

## 2. ATC model screen (`/atcmodel`)
- **Dialog (`create-atcmodel`):** a Forms section integrated into the existing dialog ("no separate dialog").
  - Add via autocomplete; the Specialist / Participant toggle is required before Save; remove; rows sorted by name.
  - **No template functions:** `formRows` / `formOptions` / `formsIncomplete` are variables refreshed by `updateForms()`,
    plus trackBy. The first version used `formName()` / `formOptions()` / a getter; the operator ruled function binding
    out after the View ATC freeze (§4).
  - The picker offers **active forms only** (`delete !== true`). This is filtered client-side, because most `delivery forms`
    docs have no `delete` field and a Firestore `!=` filter drops docs missing the field. See §7 for the fix path.
  - "Form not found" is kept for a configured form that's gone or soft-deleted (operator: keep).
- **Table (`view-atcmodel`):** a Forms column with the form **names** (first a count; the operator asked for names).
  Names are read only for the configured ids (document-id `in`, 30 per query), each id once.

## 3. Form screen (`/formtemplate`)
- **Specialist Fill (`?atcid=`).**
  - Before saving, `findCurrentAtc` follows `upgradedto` to the newest version. Check "upgraded" BEFORE "deleted",
    because an upgraded version also has `isdelete:true`.
  - Deleted → alert, nothing saved. Then save the answer (`atcid` = latest, `filledby: specialist`).
  - Then **one transaction** (`recordOnAtc`) re-runs the chain walk and sets `formsubmitted.{formid}`. The operator asked
    for a transaction against the rare edit-during-submit race; Firestore retries it on the new version.
  - Then `window.close()`; the View ATC list is live, so the row flips by itself.
- **Specialist resubmit (Edit).** The operator chose **the B!G edit logic** over "new answer + re-point".
  - Opened with `?patchdata=formsByClient/{answerid}&atcid=`: prefilled, editable.
  - The existing `onUpdate()` (copy the old answer to `formsByClient log`, then `setDoc` merge on the same doc) gets a
    **Preview & Update** button, shown only for `formpatch && atcid`. Its old button had been commented out since the
    first commit, so B!G edit on this screen was unreachable.
  - Same ATC check + `recordOnAtc` + tab close. The participant app's Resent flow will use the same logic (Flutter D1).
- **Video bug (found by the operator, pre-existing since `bc29bb06`, 2026-07-23).**
  - The code replaced a video field's `options[0]` with a `SafeResourceUrl` **inside `submittedClientForm`**, the object
    that is written to Firestore. So every form with a video failed to autosave ("Unsupported field value:
    SafeResourceUrlImpl") and failed to submit (the error was swallowed and the spinner just closed).
  - Also `<source [src]>` does not unwrap a SafeResourceUrl. It rendered the text "SafeValue must use [property]=binding",
    so videos **never played**.
  - Fix: the saved form keeps the plain URL; playback uses `videoUrl[index]` (a plain string + `ngsw-bypass`, like
    audio). Confirmed by the operator ("video playback is working").
  - **Why the tests missed it:** every seeded form was label + one Text field. The e2e now drives a form with every
    widget type (see the test journal).
- **Number fields save as text (`"42"`).** Pre-existing, NOT changed — awaiting operator review.
  - The `<input [type]="form.type">` at html :179 / :496 binds the type at runtime, so Angular's NumberValueAccessor
    (selector `input[type=number]`, a static attribute) never attaches and the default string accessor is used.
  - `processFormArrayValues()` (ts :663) saves the value as-is.

## 4. View Prescribed ATC (`/viewprescribedATC`)
- **Behaviour (the operator's step-1 list):**
  - Collapsed validated ATC with model forms → "X of N forms submitted". Unvalidated → only the existing tag. Model
    without forms → no UI change.
  - Opened validated ATC → the Forms card.
- **The freeze.** The first version froze the screen on "View Full ATC". Root causes:
  - a child component whose `get rows()` built new objects with no trackBy, so every change detection destroyed and
    re-created every row (probe: 10 of 10 CDs rebuilt);
  - template function bindings on a page with live listeners;
  - a whole-collection `delivery forms` read on open.

  The operator asked for "simple direct if conditions and buttons inside the component". So the child panel and the
  shared helper were **deleted**; everything is inline, with lookup maps worked out once (`mapFormsCount`,
  `mapFormRows`, `mapForm`, `mapFormRequests`) plus `trackBy`.
- **Loads (as the operator specified):**
  - list = ATC docs + all `atc model` docs;
  - open = corrections / procedures / notes (as before), plus only that model's `delivery forms` (document-id `in`,
    cached in `mapForm` across ATCs), plus a **live listener on `atc_form_requests` where `profileid` == participant AND
    `atcid in [this id + editedfrom chain]`**. It is started after `getATCVersion` resolves (`mapAtcVersionLoad`
    promise), so no version is missed.
  - It is killed with the ATC's other subscriptions: on collapse, page leave, or a new set of ATCs.
- **Rows:**
  - specialist forms: Fill form / View / Edit;
  - participant forms: Send / Revoke / Resend / View (participant buttons were brought into step 1 by the operator);
  - delivery form doc gone → row hidden; soft-deleted and not answered → buttons disabled + "This form was deleted and is
    no longer required"; soft-deleted and answered → View only (no Edit).
- **View** reuses the participant forms screen's `FormOverlayViewComponent` exactly as it is (operator: "reuse exactly,
  don't make changes").
- **Access — no extra check (operator, final).**
  - The list query already limits a non-super user to the ATCs they authored; super roles (ah / admin / developer /
    mentor) see all. So whoever sees an ATC may act on its Forms **and** its EI Review log.
  - Two intermediate versions were built and removed the same day:
    - "the review-log rule", which looped over every adjustment's `implementationagent`;
    - an ATC-level `implementationagent` version (that array is maintained by the `procedureOnWrite` Cloud Function).
  - The review-log template's three `canWriteReview(atc)` calls (function binding) went with them, and so did the
    now-unreachable read-only note.
- The **pre-existing** template functions (`atc.data()`, `reviewRows()`, filter lists, …) are untouched: the operator
  deferred that optimisation.

### 4b. Forms card redesign (operator: "status and button actions are confusing")
Mockup approved as shown, then built:
- **Two groups:** "Forms you fill" and "Forms the participant fills in the app" (replacing the per-row
  Specialist / Participant label).
- **Summary line:** "X of N submitted · N waiting for participant · N for you to fill". Zero parts are left out.
- **Per row:** a coloured status pill (icon + label) + a one-line explanation + only that state's buttons:

  | Status | Explanation | Buttons |
  |---|---|---|
  | To fill | You haven't filled this yet | Fill form |
  | Submitted | Filled by you | View answer, Edit answer |
  | Not sent | The participant can't see it yet | Send to participant |
  | Waiting for participant | Sent {d MMM y} | Withdraw |
  | Waiting for update | Sent back {d MMM y} to update their answer | View answer, Withdraw |
  | Submitted | Filled by the participant | View answer, Ask to update |
  | Not required | This form was deleted | none |

- **Withdraw** (was Revoke) now asks: "Withdraw this form? The participant won't be able to submit it."
- Everything per row (status, tone, icon, note, `canView` / `canEdit` / `canFill` / `canSend` / `canResend` /
  `canWithdraw`) is worked out once in `buildFormRows` into `mapFormRows` + `mapFormView`. The template reads plain
  fields only, and one `ng-template` row is shared by both groups. The `data-testid`s on the buttons are unchanged;
  `vatc-form-note`, `vatc-forms-summary` and `vatc-forms-group-*` are new; `vatc-form-deleted` is gone (the note says it).

## 6. Delivery forms (`/deliveryactivities`, `update-delivery` dialog)
- Every save (incl. the autosave) writes `delete`: false for a new or active form; true is kept for a deleted form, so
  saving never undeletes.
- **Restore form** (a deleted form shows Restore instead of Delete) → `delete:false`. There was no undelete before.

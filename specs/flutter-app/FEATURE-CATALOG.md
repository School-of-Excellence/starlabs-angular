# breakthroughs-flutter — FEATURE CATALOG (master e2e coverage matrix)

> The master coverage matrix for the **breakthroughs-flutter** participant app (native Flutter, branch `development`). One row per feature across all **18 evidence-backed cluster maps** in `specs/flutter-app/clusters/*.md` (each cluster doc carries the `file:line` evidence; this catalog consolidates them for e2e planning). This is consumed to plan the full e2e suite: each **e2e-testable** feature → a seed precondition + an **anti-circular assertion** on the doc the *app itself writes* (`Writes = assertion target`). Read-only features assert rendered state instead.
>
> **Anti-circular principle:** the assertion target is the Firestore doc the app writes as a side-effect of the user action — never the seed doc we planted. For read-only features the target is a rendered widget (prefer a stable `Key('e2e-…')` where the screen lacks one; flagged in the e2e note).
>
> **ATC firewall:** every feature tagged `atcTouch:true` is e2e-testable=**No** with reason **"ATC OFF-LIMITS — CI-excluded (firestore-atc / atc_* collections)"**. Reference-only config (`atc model` / `atc taxonomy` / `atcmodel level config`) is SAFE per `CLAUDE.md` and does **not** make a feature ATC.
>
> **Named-DB note:** forms use a separate Firestore database `firestore-forms`; ATC uses `firestore-atc` (OFF-LIMITS). Several writes target these — the seeder/asserter must address the correct database.
